# 每日高价值情报邮件

管理员可在导航中的「邮件推送」管理多个收件邮箱，统一配置总开关、内容情报价值分门槛和每日发送时间。邮件同时汇总内容情报和GitHub项目研究日报。内容情报默认门槛为严格大于70分（71分及以上），GitHub日报按研究流程已经选出的结果发送，默认每天北京时间09:00开始检查，等待当天采集和研究完成后汇总发送。

## 收件邮箱管理

- 支持新增、编辑邮箱地址及名称或备注，按邮箱或名称搜索，单独启用、暂停和删除。
- 每条记录只填写一个地址。地址去除首尾空格并转为小写，同一个邮箱不能重复添加；无效地址、多个地址和控制字符会被拒绝。
- 只有总开关和邮箱自身开关同时启用时才投递。开启总开关前，至少需要一个已启用的邮箱。总开关已开启时仍可暂停全部邮箱，恢复其中任一邮箱后继续接收。
- 每个邮箱分别发送邮件，收件人只看到自己的地址；内容去重、投递状态、自动重试和Worker租约按邮箱独立处理。某个邮箱拒收不会阻止其他邮箱接收。
- 点击邮箱行中的「查看记录」可筛选该邮箱的历史投递。发送记录也支持按邮箱筛选。
- 删除邮箱会停止其后续发送和自动重试，已保存的投递记录和原文去重凭据仍保留。重新添加同一地址后，已推送内容不会重复发送。

## 内容选择与发送规则

- 仅选择已完成分析、通过主雷达准入规则并且价值分严格超过配置门槛的内容；不会绕过系统测试相关性门槛，也不会发送观察池或已过滤内容。
- GitHub部分按已发布日报的项目条目发送，准入筛选由GitHub研究流程完成；邮件不会再次按价值分或项目当前状态筛空已发布日报，后续忽略、归档或重新分析状态变化也不会改写日报是否有内容的判断。只有内容情报和GitHub日报都为空才跳过，任一部分有待发送新结果都发信。
- 新邮箱从第一次启用时开始，接收此后新完成分析的内容；不自动补发启用前的历史情报。修改收件邮箱会重新建立时间窗口。暂停后恢复同一个邮箱会保留原窗口，可以接收暂停期间新完成分析的内容。
- 根据分析完成时间筛选，避免文章发布时间较早或采集后延迟分析的情报被遗漏。重分析或删除后重新采集同一原文，不会给已发送过的邮箱重复推荐。
- GitHub按日报生成时间收录，启用前生成的历史日报不自动补发。同一项目按仓库名称为每个邮箱独立去重，日报重复收录或研究记录删除后重建不会重复推荐；其他邮箱仍可独立接收。
- 正文分为内容情报和GitHub项目研究，两部分分别按价值分从高到低展示标题、评分、来源或星数、摘要、落地建议和链接；提供纯文本和HTML正文，并附UTF-8 Markdown完整报告，包括内容场景、风险、相关链接和项目的价值分析、应用场景、落地建议。
- 每封两类内容合计最多100条，超过上限的未发送内容留待后续日报。两类都有积压时为GitHub研究保留最多50条名额，其余名额用于内容情报。
- Worker按「采集 → 内容分析 → GitHub自动发现、研究与日报发布 → 邮件检查」顺序执行。发送前要求所有启用信源当天至少成功采集一次、内容分析队列已完成，以及当天GitHub研究成功完成；成功探索但没有新项目也算研究完成，不要求生成空日报。
- 发送时间已到而长采集间隔尚未到时，会补齐当天尚未执行的信源采集和GitHub探索，避免24小时执行间隔漂移到邮件发送之后。失败任务仍遵循原有重试间隔；内容每轮批量分析，有积压时会等待后续轮次处理完成。持续失败会延迟邮件：采集失败需修复或停用故障信源，内容或项目分析失败需修复分析配置并等待重试，不能将失败当作当天无内容。
- 前置任务尚未完成时不会创建「无新内容」记录或冻结当天邮件。全部完成后，内容情报有结果、GitHub日报为空时发送；内容情报为空、GitHub日报有结果时发送；两者都有时合并发送；两者都为空才不发信，后台记录「无新内容」。当天后续出现新结果可复用这条记录发送。每个邮箱每天最多发送一封，已经发送之后才产生的新内容进入后续日报。
- 时间统一使用北京时间；邮件按分析完成时间、日报生成时间归集，与页面按原文发布时间展示的日期互不影响。实际投递会受到Worker轮询、采集和分析耗时影响。停机后恢复会在完成当天前置任务后汇总尚未发送的符合条件内容，不逐日发送历史空报。
- 此配置为平台级收件邮箱列表，只有管理员可以读取、修改或重试，不是各用户独立订阅。

## 配置发件服务

后端API和Worker均需读取同一份SMTP配置。Docker Compose已为两个服务映射以下环境变量，部署目录的`.env`可参考根目录`.env.example`：

```dotenv
ATI_SMTP_HOST=smtp.example.com
ATI_SMTP_PORT=587
ATI_SMTP_SECURITY=starttls
ATI_SMTP_FROM=radar@example.com
ATI_SMTP_USERNAME=radar@example.com
ATI_SMTP_PASSWORD=replace-with-mail-provider-app-password
ATI_SMTP_TIMEOUT_SECONDS=30
```

`ATI_SMTP_SECURITY`支持`starttls`和`ssl`两种加密连接方式。端口及授权码要求请以发件服务商的配置为准；使用`ssl`的服务通常配置465端口。证书验证保持开启。允许受信任SMTP中继不配置认证，但用户名和密码必须同时填写或同时留空。发件地址应为服务商允许的邮箱，不能填写显示名称或多个地址。

配置只通过后端环境变量提供，页面和接口不会返回凭据。未完整配置时页面提示「尚未配置发件服务」，Worker不会发信，也不会消耗当天待发送内容。默认关闭邮件订阅，迁移和部署本身不会自动发送邮件。

本地运行时，应为API和Worker设置对应环境变量，或使用`apps/api/.env`。根目录`.env`由Docker Compose读取，本地后端不会自动读取根目录的文件。

## 升级与启用

1. 应用数据库迁移：在`apps/api`运行项目虚拟环境中的`alembic upgrade head`。Windows可使用`.venv\Scripts\alembic.exe upgrade head`。
2. 配置上述发件参数并更新API与Worker；重新构建前端以显示邮件配置入口。Docker Compose部署可运行`docker compose up -d --build api worker web`，迁移服务需成功完成。
3. 使用管理员账号打开「邮件推送」，新增并启用收件邮箱，设置门槛与时间，打开总开关后保存。
4. 确保Worker持续运行，在「发送记录」检查投递结果。真实邮箱验收需要可用的SMTP服务和至少一条启用后完成分析的合格情报。

此功能依赖后端、数据库和Worker，只有前端静态产物的部署环境无法执行邮件任务。生产发布仍需遵守部署文档中的提交号、容器静态资源哈希和浏览器资源哈希三点核验。

从单邮箱版本升级时，迁移`20261011_01_email_recipients`会把原收件邮箱转为列表中的一条记录，保留已有总开关、门槛、时间、订阅起点和历史投递。请同时升级API、Worker和前端。降级到旧单邮箱版本只能保留一个邮箱（优先最早添加的启用邮箱），降级前应备份收件邮箱列表。

迁移`20261011_02_email_github_items`增加按邮箱保存的GitHub项目推送凭据，已有内容情报投递记录保持有效。部署前执行迁移；降级移除此表会丢失GitHub去重凭据，应提前备份。

## 失败与重试

每封邮件发送前会持久化收件邮箱、报告快照和原文去重凭据。明确连接、认证或拒收失败会自动重试，首次失败后约5分钟进行第二次尝试，第二次失败后约15分钟进行第三次尝试。每轮最多尝试3次，达到上限后管理员可点击「重试」开启新一轮尝试；页面次数显示本轮尝试次数。重试使用原报告，不会因后续新内容或评分调整而改写附件。

连接中断或进程退出可能导致无法判断发件服务是否已接受邮件，这类记录标为「待确认」，不自动重发。管理员应核对收件箱后点击「重试」；若邮件实际已收到，手动重试可能造成重复。发件服务已经确认接收后，退出连接失败不会被误判为投递失败。页面「已发送」表示发件服务接受投递，不代表最终一定到达收件箱。

多Worker通过每个邮箱的数据库租约协调任务，按邮箱与北京时间日期约束日报唯一性。发送成功和重分析去重记录跨Worker重启保留。待重试和待确认邮件中的原文会被保留，后续日报不会再次把它们当作新内容。停用总开关、暂停、删除或修改邮箱后不会继续自动向旧邮箱重试；恢复原邮箱且总开关启用后可以处理原来的待重试记录。已经提交给发件服务的邮件无法撤回。

## 接口

以下接口均要求管理员权限：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/email-digest/preferences` | 读取订阅配置和发件服务配置状态，凭据不返回 |
| `PUT /api/v1/email-digest/preferences` | 保存总开关、`value_threshold`和`send_time`；启用前须存在已启用邮箱 |
| `GET /api/v1/email-digest/recipients` | 读取收件邮箱列表 |
| `POST /api/v1/email-digest/recipients` | 新增邮箱，字段为`email`、`name`（可选）、`enabled`（默认true） |
| `PATCH /api/v1/email-digest/recipients/{id}` | 修改地址、名称或启用状态，只提交要修改的字段 |
| `DELETE /api/v1/email-digest/recipients/{id}` | 删除收件邮箱，保留历史记录 |
| `GET /api/v1/email-digest/deliveries?offset=0&limit=20&recipient=reader@example.com` | 分页查看发送记录，`recipient`筛选参数可省略 |
| `POST /api/v1/email-digest/deliveries/{id}/retry` | 将失败或待确认邮件重新加入队列，由Worker执行 |
