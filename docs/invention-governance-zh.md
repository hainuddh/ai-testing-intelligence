# 潜在发明管理规则

本文定义项目在设计和实现新技术机制时的发明识别、证据积累、公开审查和申请决策流程。它不记录未公开的发明细节。具体候选、实验数据和查新材料保存在项目根目录下被 Git 忽略的 `.invention-record.md` 中。

## 1. 维护原则

- 不以专利数量为目标，不把常规框架使用、业务规则、参数调整或已知机制的简单拼接包装成发明。
- 产品需求首先按正确性、安全性、可维护性和成本收益设计；存在多种正确方案时，再优先考虑具有明确技术因果关系且难以替代的方案。
- 新机制在详细设计、实现完成、获得实验结果、准备公开代码或文档时，均应检查潜在发明记录。
- 未公开的技术结构、实验结果和权利要求构思不得写入公开仓库、Issue、PR、镜像说明、演示材料或公开聊天记录。
- 已公开不等于不能记录，但必须准确记录首次公开时间、载体、范围和证据，交由专利代理师判断影响。

## 2. 候选记录字段

每个候选至少记录以下内容：

| 字段 | 要求 |
| --- | --- |
| 编号和名称 | 使用稳定编号，例如 `INV-001`，名称描述技术机制而非产品宣传语 |
| 记录状态 | `观察`、`验证中`、`查新候选`、`申请评估`、`暂停`、`放弃` |
| 首次构思 | 日期、参与人及可验证的原始材料位置 |
| 此前无法解决的问题 | 描述已有方案在安全、计算资源、一致性、时延或准确性上的具体限制 |
| 结构差异 | 说明组件、数据结构、状态转换及相互依赖关系，不只描述功能效果 |
| 反直觉设计 | 说明为什么本领域人员不会自然采用，若不存在则明确写“未发现” |
| 技术效果 | 给出指标、基线、实验环境、样本和重复方法，不使用仅有业务含义的表述 |
| 可替代性 | 列出最接近替代方案及其代价，判断是否能被简单替换或绕开 |
| 实现证据 | 私有设计稿、代码位置、提交或实验报告；区分已实现和设想 |
| 公开状态 | `未公开`、`部分公开`、`已公开`；记录最早日期、URL/提交和公开范围 |
| 现有技术 | 已知专利、论文、产品和开源实现，以及尚未检索的范围 |
| 下一门槛 | 进入下一成熟度所缺的实现、数据、检索或法律判断 |

## 3. 成熟度等级

| 等级 | 定义 | 允许动作 |
| --- | --- | --- |
| `L0 线索` | 只有问题或想法，没有明确结构差异 | 私有记录，不安排查新 |
| `L1 机制` | 有可描述的技术结构，但未实现或未与现有方案对比 | 原型设计和内部评审 |
| `L2 原型` | 核心机制已实现，能够重复运行 | 建立基线和实验方案 |
| `L3 证据` | 具有可复现实验，显示显著技术效果，并完成初步替代分析 | 启动专业查新候选评审 |
| `L4 查新` | 完成专利和非专利文献检索，仍存在可保护的区别特征 | 交专利代理师评估和撰写 |
| `L5 申请` | 权属、发明人、公开状态和申请范围已确认 | 先申请，后公开相关实现 |

成熟度不能仅因完成代码而提升。`L3` 必须同时满足：

- 核心结构不是已知机制的简单并列；
- 至少一个区别特征对技术效果具有必要因果关系；
- 与最接近基线相比有预先定义、可复现的显著改进；
- 已分析两种以上可替代方案及其绕开成本；
- 公开状态和原始证据完整。

## 4. 显著效果标准

每个候选在实验前自行设定指标和通过阈值，避免看到结果后选择性解释。适用指标包括：

- 安全：攻击成功率、越权访问率、异常输出准入率；
- 资源：模型调用数、token、峰值内存、网络字节、数据库扫描行数；
- 性能：吞吐量、P95/P99 时延、恢复时间；
- 一致性：重复提交数、旧版本覆盖数、错误状态转换数；
- 质量：在固定召回率下的误报率，或在固定误报率下的召回率；
- 可恢复性：故障注入后的数据损坏数、重复副作用数和恢复时长。

“体验更好”“更智能”“情报价值更高”不能单独作为技术效果。

## 5. 方案设计检查

设计非平凡功能时依次检查：

1. 这是新的技术问题，还是普通业务需求？
2. 常规方案是什么，其明确缺陷是什么？
3. 新方案是否改变了数据结构、控制流、状态关系或资源调度方式？
4. 各区别特征是否协同产生一个技术效果，而不是各自独立工作？
5. 是否存在反直觉取舍，例如局部增加计算以显著减少全链路计算？
6. 删除任一区别特征后，技术效果是否明显消失？
7. 竞争者能否用同等常规组件轻易绕开？
8. 如何通过对照和故障注入重复验证？
9. 实现或说明是否已经对外公开？

如果答案只体现业务字段、提示词内容、界面流程或固定阈值，应按普通工程方案处理，不作为发明候选。

## 6. 公开前检查

准备提交公开仓库、发布镜像、部署公开演示或对外介绍前：

1. 检查本次变更是否对应 `.invention-record.md` 中 `L1` 以上候选。
2. 若候选仍标记为未公开，停止公开包含核心区别结构的材料。
3. 记录拟公开的文件、提交、接口、流程图和实验数据范围。
4. 由项目负责人决定放弃、先申请或缩小公开范围。
5. 完成决定后更新候选的公开状态和证据。

该检查不应被用于隐藏安全漏洞。影响用户或系统安全的问题仍应及时修复；专利流程不得阻止必要的安全响应。

## 7. 查新触发条件

候选达到 `L3` 后才安排正式查新。查新至少覆盖：

- 中文和英文关键词及同义词；
- IPC/CPC 分类及相邻分类；
- 专利、论文、标准、产品文档和开源项目；
- 单篇文献的新颖性分析；
- 多篇文献组合的创造性分析；
- 申请人自身公开和潜在抵触申请风险。

快速网络搜索只用于淘汰明显常规方案，不等同于法律意义上的查新或自由实施分析。
